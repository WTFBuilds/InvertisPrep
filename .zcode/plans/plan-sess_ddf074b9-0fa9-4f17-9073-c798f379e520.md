# Backend Performance Optimization Plan for InvertisPrep

## Problem Analysis

The backend deployed on Render is experiencing slow response times for:
1. **PYQ loading** - Slow filtering and listing of PYQ papers
2. **Departments page loading** - Slow department/branch/session data fetching  
3. **PDF viewing/downloading** - Watermarking happens on every request without caching

## Root Causes Identified

### 1. **No Caching Strategy** (Highest Impact)
- `pdfCache` LRU cache is defined in `utils/cache.js` but **never used** in pdfController
- Every PDF view/download triggers: Cloudinary fetch → pdf-lib watermark → response
- Department/Branch/Session lists fetched on every request without caching

### 2. **Database Query Issues**
- PYQ queries don't use `.lean()` for read-only operations
- Multiple `.populate()` calls in hot paths
- Department/Branch queries lack projections (fetching full docs)

### 3. **MongoDB Connection Configuration**
- Default connection pool (100) not tuned for Render free tier
- No keep-alive/socket timeout configuration

### 4. **Cloudinary Requests**
- No HTTP keep-alive for Cloudinary axios requests
- Fetching full PDF from Cloudinary on every view/download

## Implementation Plan (Phased Approach)

### Phase 1: Quick Wins - Caching (High Impact, Low Risk)
**Files to modify:**
1. `server/src/controllers/pdfController.js` - Implement PDF watermark caching using existing `pdfCache` LRU
2. `server/src/controllers/departmentController.js` - Add caching for departments/branches (5-min TTL)
3. `server/src/controllers/sessionController.js` - Add caching for sessions (5-min TTL)
4. `server/src/controllers/branchController.js` - Add caching for branches (5-min TTL)
5. `server/src/utils/cache.js` - Already has `getCache`/`setCache`/`pdfCache` infrastructure

**Implementation:**
- PDF caching: Cache key `watermarked:${paperId}:${userId}:${minuteWindow}` with 60s TTL
- Reference data caching: Cache keys like `departments:all`, `branches:${deptId}`, `sessions:all` with 5-min TTL
- Invalidate caches on admin write operations (create/update/delete)

### Phase 2: Database Query Optimization (Medium Effort)
**Files to modify:**
1. `server/src/controllers/pyqController.js` - Add `.lean()` to public queries, optimize projections
2. `server/src/models/PYQPaper.js` - Add compound indexes for common filter combinations
3. `server/src/models/Department.js` - Add index for active departments
4. `server/src/models/Branch.js` - Add compound index for department + active

**Key indexes to add:**
```javascript
// PYQPaper - compound for filtered listings
{ departmentId: 1, branchId: 1, semester: 1, verified: 1, isActive: 1 }
{ departmentId: 1, verified: 1, isActive: 1, year: -1, downloads: -1 }
// Department
{ isActive: 1, name: 1 }
// Branch
{ departmentId: 1, isActive: 1, name: 1 }
```

### Phase 3: Infrastructure Tuning (Medium Effort)
**Files to modify:**
1. `server/src/config/database.js` - Add connection pool tuning for Render free tier
2. `server/src/services/cloudinaryService.js` - Add axios keep-alive agent
3. `server/src/middleware/rateLimit.js` - Tune rate limits (separate read vs write)

**Connection pool config:**
```javascript
mongoose.connect(mongoURI, {
  maxPoolSize: 50,  // Reduced for Render free tier memory
  minPoolSize: 5,
  socketTimeoutMS: 45000,
  serverSelectionTimeoutMS: 10000,
  heartbeatFrequencyMS: 10000,
  family: 4,  // Force IPv4
});
```

**Axios keep-alive:**
```javascript
import http from 'http';
import https from 'https';

const axiosInstance = axios.create({
  httpAgent: new http.Agent({ keepAlive: true, maxSockets: 10 }),
  httpsAgent: new https.Agent({ keepAlive: true, maxSockets: 10 }),
  timeout: 30000,
});
```

### Phase 4: Advanced (Lower Priority)
- Redis-based caching for multi-instance scaling
- CDN/Edge caching for static reference data
- Request/response compression tuning

## Expected Performance Gains

| Optimization | Expected Improvement |
|--------------|---------------------|
| PDF Watermark Caching | 70-90% faster PDF view/download for repeat views |
| Department/Branch Caching | 80-95% faster page loads for navigation |
| Database Query Optimization | 30-50% faster PYQ filtering |
| Connection Pool Tuning | Reduced connection overhead, fewer timeouts |
| Cloudinary Keep-Alive | 20-40% faster PDF fetch from Cloudinary |

## Rollout Strategy
1. **Deploy Phase 1 first** (caching) - immediate impact, zero risk
2. **Monitor metrics** for 24-48 hours  
3. **Deploy Phase 2** (indexes) - requires database migration
4. **Deploy Phase 3** (connection pool) - monitor for connection errors
5. **Phase 4** - as needed based on metrics
